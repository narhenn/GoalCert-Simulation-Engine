How it works (simple version)

  1. Engine runs the scenario as normal (deterministic model)
  2. When an attack step succeeds on a modeled asset that has a VM binding, the Execution Bridge fires the same technique on the real VM using Atomic Red Team
  3. The Detection Bridge then queries Wazuh to check if the SIEM actually detected the attack
  4. The report shows modeled vs actual results side by side — "Model says detected in 90s, SIEM actually detected in 47s"

4. Prerequisites Checklist

  • Docker Desktop installed and running (you have this)
  • Docker Desktop allocated at least 4GB RAM (currently 2GB — need to increase)
  • VirtualBox 7+ installed (brew install --cask virtualbox)
  • Vagrant 2.4+ installed (brew install --cask vagrant)
  • Windows Server 2019 Vagrant box (or Windows 10 evaluation ISO)
  • ~50GB free disk space (Windows VMs are large)
  • Python packages: pip3 install pywinrm requests

Your Docker Desktop only has 2GB RAM allocated. Wazuh needs at least 4GB. Go to Docker Desktop → Settings → Resources → Memory → set to 4GB minimum (6GB recommended). Restart Docker after changing.

5. Step 1: Deploy Wazuh SIEM (Docker)

1

Increase Docker memory to 4GB+

Docker Desktop → Settings → Resources → Memory → 4096 MB → Apply & Restart

2

Start Wazuh stack

cd ~/Downloads/Goalcert_Simulation_Engine-main/Goalcert_Simulation_Engine-main/infrastructure
docker compose -f docker-compose.wazuh.yml up -d

Wait 2-3 minutes for all services to initialize.

3

Verify Wazuh is running

# Check all 3 containers are healthy
docker compose -f docker-compose.wazuh.yml ps

# Test the Indexer API (what the bridge queries)
curl -k -u admin:SecretPassword https://localhost:9200/_cluster/health?pretty

# Open the Dashboard
open https://localhost:5601
# Login: admin / SecretPassword

The Wazuh Dashboard at https://localhost:5601 is what you show Prem. It's a real SIEM showing real alerts from real VMs. The bridge queries the Indexer API at :9200 programmatically.

6. Step 2: Provision Windows VMs

Option A: Vagrant (automated, recommended)

1

Install VirtualBox and Vagrant

brew install --cask virtualbox vagrant
2

Download Windows box

# Microsoft provides free evaluation Windows boxes
vagrant box add gusztavvargadr/windows-server-2019-standard

This downloads a ~6GB Windows Server image. Takes a while.

3

Bring up VMs

cd ~/Downloads/Goalcert_Simulation_Engine-main/Goalcert_Simulation_Engine-main/infrastructure

# Start DC01 first (it sets up Active Directory)
vagrant up dc01

# Then WS01 (joins the domain)
vagrant up ws01

Each VM takes 10-15 minutes to provision (AD setup, WinRM, Sysmon).

Option B: Manual VM setup

If Vagrant doesn't work (Apple Silicon Macs can't run x86 VirtualBox VMs), use UTM or VMware Fusion:

  1. Download Windows Server 2019 evaluation ISO from Microsoft
  2. Create a VM in UTM/VMware with 4GB RAM, 40GB disk
  3. Install Windows, set IP to 192.168.56.10
  4. Enable WinRM: 
    winrm quickconfig -force
winrm set winrm/config/service '@{AllowUnencrypted="true"}'
winrm set winrm/config/service/auth '@{Basic="true"}'
Set-Item WSMan:\localhost\Service\AllowUnencrypted -Value true
  5. Set firewall rule: netsh advfirewall firewall add rule name="WinRM" dir=in action=allow protocol=TCP localport=5985

Apple Silicon Macs (M1/M2/M3) cannot run x86 Windows VMs in VirtualBox. Use UTM (free, ARM-based) or VMware Fusion (free for personal use). The Vagrantfile won't work on Apple Silicon — use Option B.

7. Step 3: Install Sysmon + Wazuh Agent

Run these on each Windows VM (DC01 and WS01):

1

Install Sysmon (generates the attack telemetry)

# On the Windows VM (PowerShell as Admin):
# Download Sysmon
Invoke-WebRequest -Uri "https://download.sysinternals.com/files/Sysmon.zip" -OutFile C:\Sysmon.zip
Expand-Archive C:\Sysmon.zip -DestinationPath C:\Sysmon

# Download SwiftOnSecurity config (best detection coverage)
Invoke-WebRequest -Uri "https://raw.githubusercontent.com/SwiftOnSecurity/sysmon-config/master/sysmonconfig-export.xml" -OutFile C:\Sysmon\sysmonconfig.xml

# Install Sysmon with config
C:\Sysmon\Sysmon64.exe -accepteula -i C:\Sysmon\sysmonconfig.xml
2

Install Wazuh Agent (forwards logs to SIEM)

# On the Windows VM (PowerShell as Admin):
# Use the script from infrastructure/
.\install-wazuh-agent.ps1 -WazuhServer "192.168.56.30"

# OR manually:
Invoke-WebRequest -Uri "https://packages.wazuh.com/4.x/windows/wazuh-agent-4.9.0-1.msi" -OutFile wazuh-agent.msi
msiexec /i wazuh-agent.msi /q WAZUH_MANAGER="192.168.56.30" WAZUH_AGENT_NAME="DC01"
net start WazuhSvc
3

Verify agent connects to Wazuh Manager

# From your Mac:
curl -k -u wazuh-wui:MyS3cr37P450r.*- https://localhost:55000/agents?pretty

# Should show DC01 and WS01 as "active"

8. Step 4: Install Atomic Red Team

Run on each Windows VM:

# PowerShell as Administrator on the VM:

# Allow script execution
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope CurrentUser -Force

# Install Atomic Red Team
IEX (IWR 'https://raw.githubusercontent.com/redcanaryco/invoke-atomicredteam/master/install-atomicredteam.ps1' -UseBasicParsing)
Install-AtomicRedTeam -getAtomics -Force

# Verify it works (dry run)
Invoke-AtomicTest T1003.001 -ShowDetailsBrief

Atomic Red Team is a library of ~1,500 test scripts that safely execute real MITRE ATT&CK techniques. Each test has a unique GUID. The bridge maps engine technique keys to specific test GUIDs.

9. Step 5: Configure the Bridge

1

Install Python dependencies

pip3 install --break-system-packages pywinrm requests
2

Create bridge config

cd ~/Downloads/Goalcert_Simulation_Engine-main/Goalcert_Simulation_Engine-main/infrastructure
cp bridge-config.example.json bridge-config.json

# Edit bridge-config.json with your actual VM IPs and credentials
3

Register bridges at startup

Add to backend/app/main.py (after init_db):

import json, os
config_path = os.path.join(os.path.dirname(__file__), "../../infrastructure/bridge-config.json")
if os.path.exists(config_path):
    from app.engine.bridge.atomic import AtomicExecutionBridge
    from app.engine.bridge.wazuh import WazuhDetectionBridge
    from app.engine.bridge.registry import register_bridges
    cfg = json.load(open(config_path))
    register_bridges(
        execution=AtomicExecutionBridge(),
        detection=WazuhDetectionBridge(
            indexer_url=cfg["wazuh"]["indexer_url"],
            username=cfg["wazuh"]["username"],
            password=cfg["wazuh"]["password"],
        ),
    )
4

Add VM bindings to scenario assets

In the Launch page or scenario JSON, add vm to assets:

12. Troubleshooting

WinRM connection refused

# On the Windows VM:
winrm quickconfig -force
winrm set winrm/config/service '@{AllowUnencrypted="true"}'
winrm set winrm/config/service/auth '@{Basic="true"}'

# Check firewall
netsh advfirewall firewall show rule name="WinRM"

Wazuh agent not connecting

# On the VM, check agent status:
Get-Service WazuhSvc
# Check agent log:
Get-Content "C:\Program Files (x86)\ossec-agent\ossec.log" -Tail 20

# From Mac, check registered agents:
curl -k -u wazuh-wui:MyS3cr37P450r.*- https://localhost:55000/agents?pretty

No alerts in Wazuh after attack

# Check Sysmon is generating events:
wevtutil qe "Microsoft-Windows-Sysmon/Operational" /c:5 /f:text

# Check Wazuh agent is forwarding:
Get-Content "C:\Program Files (x86)\ossec-agent\ossec.log" -Tail 10

# Check Wazuh indexer has data:
curl -k -u admin:SecretPassword "https://localhost:9200/wazuh-alerts-*/_count"

Atomic Red Team not installed

# Re-install:
IEX (IWR 'https://raw.githubusercontent.com/redcanaryco/invoke-atomicredteam/master/install-atomicredteam.ps1' -UseBasicParsing)
Install-AtomicRedTeam -getAtomics -Force

# Verify:
Get-Module -ListAvailable Invoke-AtomicRedTeam

Apple Silicon (M1/M2/M3) — can't run x86 VMs

VirtualBox doesn't support ARM. Options:

  • UTM (free) — runs ARM Windows, most Atomic tests work
  • VMware Fusion (free personal) — better Windows ARM support
  • AWS/Azure — spin up real x86 Windows VMs in the cloud ($0.10/hr)
  • Proxmox on a mini PC — cheapest production option ($200 one-time)
