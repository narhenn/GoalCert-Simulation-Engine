The Problem Prem Raised

Prem said: "This is still a tabletop simulation. We need to add VMware."

What he means: the simulation currently says "LSASS memory access by non-system process" as a text string. He wants a real Windows VM where Mimikatz actually runs, and a real SIEM that actually fires an alert. The simulation engine stays as the orchestrator, but the attacks and detections become real.

This is achievable. The architecture is a hybrid model: if a real VM exists for an asset, the engine executes the real attack; if not, it falls back to the existing model. Zero rewrite of the current engine.

The model stays as the orchestration/scoring layer. Real VMs are optional per asset. This means every existing scenario, test, and feature keeps working with zero changes.

Asset-to-VM Mapping

Execution Bridge (Python Interface)

class ExecutionBridge(abc.ABC):
    @abc.abstractmethod
    async def execute(self, spec, target) -> ExecutionResult: ...

class DetectionBridge(abc.ABC):
    @abc.abstractmethod
    async def query_detection(self, spec, target, executed_at) -> DetectionResult: ...

Two abstract classes. AtomicExecutionBridge runs Atomic Red Team tests via WinRM. WazuhDetectionBridge queries the Wazuh API for alerts matching the technique and time window.

       hostname="192.168.1.50",
       username="admin", password="pass")

# Option 2: pywinrm (direct WinRM)
import winrm
s = winrm.Session('https://target:5986/wsman',
    auth=('admin', 'P@ss'), transport='ntlm')
r = s.run_ps('Invoke-AtomicTest T1003.001 -TestNumbers 2')
print(r.std_out.decode())
Safe ransomware simulation

Atomic Red Team's T1486 tests encrypt only canary test files (created in %TEMP%), not real data. The -Cleanup flag deletes them. VMs run on isolated networks with snapshots that revert after each exercise.

Detection: How to Verify the SIEM Caught It

Wazuh detection query (Python)
# After executing T1003.001 on WIN-TARGET at 14:30:00
import time, requests
time.sleep(60)  # wait for log pipeline latency

resp = requests.get("https://wazuh:9200/wazuh-alerts-*/_search",
    auth=("admin", "admin"), verify=False,
    json={"query": {"bool": {"must": [
        {"range": {"@timestamp": {"gte": "2026-06-08T14:30:00Z",
                                   "lte": "2026-06-08T14:35:00Z"}}},
        {"term": {"agent.name": "WIN-TARGET"}},
        {"term": {"rule.mitre.id": "T1003.001"}}
    ]}}})

alerts = resp.json()["hits"]["hits"]
detected = len(alerts) > 0
latency = alerts[0]["_source"]["@timestamp"] if detected else None

What This Means for GoalCert

Before (current): The engine says "LSASS dumped on WS-CEO" as a text string. SIEM detection is modeled with a hardcoded 90-second latency. The report says "Detection rate: 100%." It's a tabletop exercise visualizer.

After (with VMs): Mimikatz actually runs on a real Windows VM. Sysmon captures Event ID 10 (process access to LSASS). Wazuh fires rule 92652 in real time. The report says "Detection rate: 85% — Wazuh missed the cloud persistence technique but caught credential dumping in 47 seconds." That's a real training platform.

The engine doesn't change. It gains an optional vm field on each asset and two bridge classes. Every existing scenario, test, report, and feature keeps working. VMs are additive, not a rewrite.

Milestone 1 is 3-5 days of work. One Windows VM, Wazuh in Docker, 3 techniques wired through atomic-operator. That's the proof Prem needs to see.
